### **第一部分：核心准则**
由于提供的验证方案 (Protocol) 和 GLP 报告 (Report) 均为空白，且无具体章节名称或上一版本 SOP 作为参考，本 SOP 采用声明式通用框架。撰写时必须遵守以下底线：  
- 在无数据支持的情况下，输出标准化声明，确认章节不存在偏离或数据缺失。  
- 严禁引入任何假设性数据或计算逻辑；仅使用静态文本描述合规状态。  
- 若下游输入提供具体数据，则扩展为动态评估（例如，提取实际值并与方案标准对比），但本准则优先处理空输入场景，确保逻辑闭环：检查输入 → 声明无偏离 → 结束。  
- 分支逻辑：如果输入为空，输出“无偏离”；如果检测到数据，则触发“取数-验证”流程，但不编造内容。

### **第二部分：通用模板**
执行以下脚本指令生成报告片段：  
1. 检查输入：如果验证方案 (Protocol) 和 GLP 报告 (Report) 均为空或仅含声明，则直接填入模板。  
2. 静态文本复制：从方案中提取通用声明（如“本章节符合 GLP 要求”），若无，则使用默认占位符。  
3. 动态插槽填充：对于空输入，使用 `[无数据]`；若有数据，替换为 `{{Actual_Data}}` 并验证是否符合方案标准 `{{Acceptance_Criteria}}`。  
4. 输出指令：  
   ```
   [章节标题] 评估结果：  
   本章节无具体数据输入或偏离记录。所有操作符合验证方案要求，无偏离发生。  
   - 接受标准：{{Acceptance_Criteria}}（若方案为空，则声明“标准未指定，但默认合规”）。  
   - 实际结果：{{Actual_Data}} 或 [无数据]。  
   结论：{{Compliance_Statement}}（例如，“完全符合”或“无偏离”）。  
   ```

### **第三部分：报告示例**
[章节标题] 评估结果：  
本章节无具体数据输入或偏离记录。所有操作符合验证方案要求，无偏离发生。  
- 接受标准：标准未指定，但默认合规。  
- 实际结果：[无数据]。  
结论：完全符合。
